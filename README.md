# ChessPushBot

基于 RASPBOT V2 和树莓派 5 的视觉自主推棋项目，目标是在竞赛场地内识别、收集并推送棋子进入得分区。

当前仓库包含五类模型资产和分层算法目录；仿真、VIO、控制与部署程序尚未迁入。

## 自主推棋算法逻辑

算法按输入、感知、建模、决策、运动规划和执行六层组织。执行后小车与棋子的状态发生变化，相机和 IMU 重新采样，进入下一轮闭环。

```text
车载相机图像 + IMU 角速度、加速度
    ↓ 输入层：采集数据与时间戳
    ↓ 感知层：YOLO 棋子检测 + VIO 自车定位
    ↓ 建模层：坐标映射 + 世界模型
    ↓ 决策层：寻棋 / 选择目标 / 推棋 / 恢复
    ↓ 运动规划层：绕后、对准与推送路径
    ↓ 执行层：路径跟踪 → 四路电机 PWM
小车运动、棋子移动 → 相机与 IMU 重新采样
```

| 层级 | 处理逻辑与输出 |
| --- | --- |
| 输入层 | 采集车载图像、IMU 角速度与加速度，保留各自时间戳，供感知层对齐。 |
| 感知层 | YOLO 从图像输出棋子检测框；<br />VIO 结合图像与 IMU 估计自车平面位姿 `x、y、theta` |
| 建模层 | 把检测框映射为棋子场地坐标；<br />世界模型维护棋子位置 |
| 决策层 | 根据世界模型和当前的位姿，输出本轮推棋的有序棋子序列和最终得分区位置 |
| 运动规划层 | 接受决策层的决策，对决策层的路径针对真实情况做优化，防止已经进入的棋子被碰出、<br />路径上的棋子捕获失效等问题 |
| 执行层 | 接受运动规划层的规划<br />经麦轮控制生成四路电机 PWM；处理命令限幅、数据超时和停止。 |

### 层间接口约定

各层只通过带时间戳的结构化数据连接。输入层不解释图像或惯性数据，感知层不维护棋子地图，建模层不决定收棋顺序，决策层不直接生成电机 PWM。运动规划层可以改变决策层给出的实际行驶路径和动作顺序，但不能把未在世界模型中的棋子加入决策结果。执行层只接收运动规划层的可执行指令，并反馈命令执行状态。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| 输入 → 感知 | 图像、角速度、加速度及各自采集时间戳 | 对齐后的传感器数据 |
| 感知 → 建模 | YOLO 检测框、`x、y、theta` 及估计时间戳 | 带场地坐标参考的观测 |
| 建模 → 决策 | 当前位姿、棋子世界模型、得分区占用估计 | 有序棋子序列、最终得分区位置 |
| 决策 → 运动规划 | 有序棋子序列、目标得分区、当前位姿 | 可执行的收棋、对准、推送、后撤路径 |
| 运动规划 → 执行 | 带阶段和时限的运动指令 | 四路 PWM、限幅/停止状态 |

四路输出按电机编号 0、1、2、3 排列，整数范围为 `[-255, 255]`；正负表示方向，绝对值表示驱动强度，停止命令为 `[0, 0, 0, 0]`。仿真与实车应使用同一套动作定义。

VIO 局部里程计需要完成场地对齐后才能作为场地绝对位姿使用。仿真阶段可提供理想自车位姿，棋子的真实位置、接触状态和评分只供评测使用，决策模块从允许的图像与自车位姿获取信息。

## 获取与使用

```sh
git clone https://github.com/Jyikove/ChessPushBot.git
cd ChessPushBot
```

模型文件直接保存在 Git 中，无需额外下载或 Git LFS。STEP 可用 CAD 软件打开，STL 可导入切片软件，GLB 可用于三维预览。运行与部署入口将在相关代码迁入后补充。

| 资产 | 入口 | 单位及说明 |
| --- | --- | --- |
| 小车 | `assets/robot/raspbot.step` | 原厂 STEP，毫米；存在原始几何导入问题，仿真网格为外形近似 |
| 小车仿真网格 | `assets/robot/simulation.json` | OBJ 为米；配置记录装配坐标变换、推板碰撞分块及简化假设 |
| 场地 | `assets/field/field.obj`、`field.png`、`field.json` | 3×2 米；纹理与 OBJ 的 UV 配合使用，渲染器需显式绑定纹理 |
| 推板 | `assets/pusher/pusher.step`、`pusher.stl` | 毫米；宽 200、中间弧深 10、壁厚 3、安装片主体 3、安装孔周围 2（半径 3.5）、离地 3；OBJ 是已转换到仿真车体坐标的米制网格 |
| IMU 转接板 | `assets/imu_mount/imu_mount.step`、`imu_mount.stl` | 毫米；板厚 2、固定孔距 49×58、支座外径 6；搭配 14 mm 铜柱 |
| 棋子 | `assets/chess/chess.json` | 14 种棋面、按数量组成 32 枚；直径 47 mm、高 15 mm；STEP/STL 毫米、GLB 场景变换后为米 |

棋子双面文字已建模，黑方炮使用火字旁“炮”。碰撞模型简化为圆柱；质量与摩擦未实测。场地绘图区域与既有实验评分区存在差异，具体坐标保留在 `field.json` 中，不能直接视为统一后的比赛判分配置。

原厂车体来自 Yahboom RASPBOT V2 资料；场地外观依据项目提供的尺寸图；棋子按所购产品尺寸近似建模，字形和装饰未逐项实测

推板模型更新后，运行 `python assets/pusher/build_simulation.py` 同步仿真外观和圆弧碰撞分块（需 numpy、trimesh）；安装孔及孔周局部减薄在碰撞模型中填实。
