# 自主推棋仿真

从点模型筛选决策策略，再在 MuJoCo 中检验摄像头、四轮驱动、推板接触和计分。默认三维棋局为种子 77，32 枚棋，限时 120 秒。无需小车在线。仿真当前用理想自车位姿代替 VIO 输出，感知、建模、决策、运动规划和执行的职责按仓库根目录 README 的接口约定组织。

## 层级边界

- 输入层提供带时间戳的图像、IMU 角速度和加速度。
- 感知层输出 YOLO 检测框和 VIO 平面位姿 `x、y、theta`。
- 建模层把检测框映射到场地坐标，并维护棋子世界模型。
- 决策层只输出有序棋子序列和最终得分区位置。
- 运动规划层把决策结果转成可执行路径，处理靠线推送、已经进入得分区的棋子保护、路径棋捕获和推完后撤等真实约束。
- 执行层把运动指令转换成四路麦轮 PWM，并处理限幅、超时和停止。

三维仿真的 `Brain` 同时承载建模、决策和运动规划的实验性实现。迁移到实车时，应按上述边界拆分接口，不能让决策层直接依赖 PWM 或 MuJoCo 真值。

## 运行

在仓库根目录运行。已验证环境为 macOS、Python 3.12；需可用的 OpenGL 渲染环境、C++17 编译器（命令名 c++）和含 libx264 的 FFmpeg。图形后端默认 GLFW，可用 MUJOCO_GL 覆盖。

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r sim/requirements.txt
python sim/point.py                   # 十盘：连续得分线 vs 八分区，三种地图策略
BOARD_SEED=77 python sim/run.py        # 完整三维仿真；TEST_SECONDS=5 可做启动检查
BOARD_SEED=115 TEST_SECONDS=300 python sim/run.py  # 五分钟仿真，32 枚全部入区时提前结束
```

在 Windows PowerShell 中，从仓库根目录打开实时四视图（需 Python 3.12 和 PATH 上的 `c++`、`ffmpeg`）：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r sim/requirements.txt
$env:SIM_LIVE = '1'
$env:SIM_APPEARANCE = 'photo-room'
.\.venv\Scripts\python.exe sim/run.py
```

窗口随仿真更新，仍会同时保存录像。按 `Esc`、`Q` 或关闭窗口可提前结束。

用 `SIM_APPEARANCE` 切换车载镜头所见的场地外观：

| 值 | 渲染环境 |
| --- | --- |
| `baseline`（默认） | 原有灯光和黑背景 |
| `overcast` | 冷色窗光、漫射顶光和较轻的地面阴影 |
| `window-sun` | 强烈斜射侧光，带围挡和物体投影 |
| `warm-room` | 弱窗光、偏暖的室内灯和较低曝光 |
| `photo-room` | 实拍参考生成的四面背景、较暗底板和多方向采样的柔和侧光 |

例如在 PowerShell 中运行 `$env:SIM_APPEARANCE='window-sun'`，再启动 `sim/run.py`。新场景基于实拍中可见的围挡、白墙、窗框与柜体进行近似建模，未使用实拍作为贴图，也没有测量现场灯光。背景只在车载视角可见，不参与碰撞；光照会影响实际送进 YOLO 的 RGB，而不只是美化回放。非默认场景的输出目录带有预设后缀，不覆盖原版结果。

非默认场景均用两根灯条（每根三个出光点）与窗侧光共同照明；围栏为哑光白色，底板保留比赛图案并产生宽而淡的高光，不模拟镜面倒影。灯条的位置、亮度和材质是近似值，不是现场测量结果。

`photo-room` 使用参考实拍生成的四面背景图 `resources/room/background.png`，固定在场地外的世界坐标平面上。背景不是实景扫描；地面保留比赛图案，并调低亮度。若同级 `field-calibration/data/images`（或 `SIM_PHOTO_DIR`）存在原始实拍，会额外叠加实拍表面细纹。渲染仍是 MuJoCo OpenGL，不是路径追踪。

非 `baseline` 场景在 `SIM_LIVE=1` 时提供 `LED strips (%)` 和 `Window light (%)` 滑杆，范围 0–200，100 为场景预设。两者分别改变灯条和窗侧光的渲染强度，下一张车载画面和 YOLO 同步生效。无窗口跑批时可用环境变量 `SIM_STRIP_LIGHT` 和 `SIM_WINDOW_LIGHT`；运行记录保存灯光变更时间与数值。背景图内的亮度是固定纹理，滑杆不会重新生成墙面的照片光照。

所有运行产物都写在仓库外。以下路径相对于仓库的上一级目录：点模型输出到 `决策层点模型实验/point-comparison/`；三维视频在 `三维仿真/视频/sim-seed-77/四视图.mp4`，核查记录在 `三维仿真/报告/sim-seed-77/`；再次运行同一种子会覆盖该目录中的同名产物。`TEST_SECONDS` 同时配置物理循环和裁判时限，裁判会在全部 32 枚入区时提前结束。四分屏依次是车载 RGB 与 YOLO 框、物理俯瞰、视觉世界模型、状态与实测速度。

## 从观察到计分

1. **观察。** 3 × 2 米场地，固定前视云台。相机 5 Hz 输出 640 × 480 RGB，单类 NCNN 检测输入 416 × 320；把检测框上缘中心投影到棋顶平面，并补偿半径。策略只用图像、模拟时钟及自身位姿（米、弧度），不读取俯瞰图、棋子真值或裁判分数。
2. **规划。** 先原地对准再直行；三维闭环在正常收棋阶段按仿真时钟每 1 秒重规划，首次规划及新一趟可立即启动；点模型对照沿用累计平移 50 cm。设 W 为已携带估计加待收枚数，E 为整趟等效路程超过首次规划单棋基准的正部。90° 转向折合 0.35 米，已走路程和转角不退回。最小化 `E + max(0,E−0.24 min(W−1,3)) − 1.15 min(W,4) − 1.15 (1−2^(−max(W−4,0)))`。前四枚各奖励 1.15，第五枚起每枚奖励为上一枚的一半。空趟排除；已带棋可直接送回。
3. **选区。** 己方边界 x=0、y=0.42…1.57 米均分八段。联合选择收棋顺序与入口中心；选区时只查该区已有估计是否小于 4。一趟可超额，不拆单。点模型的全图、被动寻棋与主动观察共用同盘布局、车速和评价窗口；视野内理想检出，推着的棋不会丢。点模型停留 0.5 秒完成整批交付，与物理裁判的即时计分不同。
4. **执行。** 控制 10 Hz，四轮输出顺序 FL、FR、RL、RR，整数 PWM −255…255；物理以 240 Hz 模拟轮速响应、驱动力和接触。进区前在区外对准，航向误差控制在约 0.05 rad（2.9°）内并允许角速度降到 8°/s 以下，随后直推；过线或触发墙距、停滞等保护即停。停留后沿原朝向倒退，脱离保护区并制动后才准转向。该放行误差配合麦轮最小 PWM，避免在 2°附近反复猎振。
   正常推送期间不为盘点而倒车。区外地图随每帧 RGB 更新，包括后撤期间；同一轨迹用最新观测位置，连续两帧看清旧位置为无检测遮挡的白色空地时从地图撤销。出视野、长时间未检测或仅一次漏检都不会据此清除，世界模型没有按时间到期的生命周期。若运动规划层检测到车体速度持续低于 0.02 m/s 且连续 1.5 秒没有接近当前目标，则先后退 0.8 秒并原地转向 0.7 秒，最多尝试两次，再重新规划。脱困失败时才标记该目标为当前执行不可达，保留其世界模型记录等待后续新观测或重新评估。分区交付账仍在后撤制动结束时核对。同一位置连续两帧稳定出现则按普通棋子登记，不强制下一趟回收。仅当观测与本趟已记账的棋子近期轨迹唯一匹配、并明显位于线外时才冲回原区一枚。模糊关联只更新地图，同次观测一棋一轨。正常后撤多留 20 cm 视距。目标分区四角都在画面内时，对区内检测框逐帧去重，仅用连续三帧共同支持的最大可见数更新分区估计；遮挡仍可能导致少计。区内观测参与已有轨迹的一对一关联。连续两帧（间隔小于 0.21 秒）匹配同一旧轨迹，且两次区内中心相距小于 3.5 cm 时撤销旧记录。未匹配的区内观测不建立棋子轨迹，区外靠线棋同样参与规划。收棋和交付前的转向不受得分区距离限制。停推后锁住朝向，直退并制动完成才开始下一趟。
5. **裁判。** 棋子中心水平投影在己方矩形内（含边界）立即得分，离开即扣回。目标为每 10 秒净得分。分区占用是策略估计，不是裁判真值。摄像头标定、摩擦与载棋估计仍需实车验证。
