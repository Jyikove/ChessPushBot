# 自主推棋仿真

从点模型筛选决策策略，再在 MuJoCo 中检验摄像头、四轮驱动、推板接触和计分。默认三维棋局为种子 77，32 枚棋，限时 120 秒。无需小车在线；当前使用理想自车位姿，不是实车 VIO。

## 运行

在仓库根目录运行。已验证环境为 macOS、Python 3.12；需可用的 OpenGL 渲染环境、C++17 编译器（命令名 c++）和含 libx264 的 FFmpeg。图形后端默认 GLFW，可用 MUJOCO_GL 覆盖。

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r sim/requirements.txt
python sim/point.py                   # 十盘：连续得分线 vs 八分区，三种地图策略
BOARD_SEED=77 python sim/run.py        # 完整三维仿真；TEST_SECONDS=5 可做启动检查
```

所有运行产物都写在仓库外。以下路径相对于仓库的上一级目录：点模型输出到 `决策层点模型实验/point-comparison/`；三维视频在 `三维仿真/视频/sim-seed-77/四视图.mp4`，核查记录在 `三维仿真/报告/sim-seed-77/`；再次运行同一种子会覆盖该目录中的同名产物。四分屏依次是车载 RGB 与 YOLO 框、物理俯瞰、视觉世界模型、状态与实测速度。

## 从观察到计分

1. **观察。** 3 × 2 米场地，固定前视云台。相机 5 Hz 输出 640 × 480 RGB，单类 NCNN 检测输入 416 × 320；把检测框上缘中心投影到棋顶平面，并补偿半径。策略只用图像、模拟时钟及自身位姿（米、弧度），不读取俯瞰图、棋子真值或裁判分数。
2. **规划。** 先原地对准再直行；按累计平移每 50 cm 重规划。设 W 为已携带估计加待收枚数，E 为整趟等效路程超过首次规划单棋基准的正部。90° 转向折合 0.35 米，已走路程和转角不退回。最小化 `E + max(0,E−0.24 min(W−1,3)) − 1.15 min(W,4) − 0.16 max(W−4,0)`。空趟排除；已带棋可直接送回。
3. **选区。** 己方边界 x=0、y=0.42…1.57 米均分八段。联合选择收棋顺序与入口中心；选区时只查该区已有估计是否小于 4。一趟可超额，不拆单。点模型的全图、被动寻棋与主动观察共用同盘布局、车速和评价窗口；视野内理想检出，推着的棋不会丢。点模型停留 0.5 秒完成整批交付，与物理裁判的即时计分不同。
4. **执行。** 控制 10 Hz，四轮输出顺序 FL、FR、RL、RR，整数 PWM −255…255；物理以 240 Hz 模拟轮速响应、驱动力和接触。进区前在区外对准，直推，过线或触发墙距、停滞等保护即停；停留后沿原朝向倒退，脱离保护区并制动后才准转向。
   正常推送期间不为盘点而倒车。只在本趟停推、停留后的原定直退与制动期间缓存区外观测；制动结束才统一核对。同一位置连续两帧稳定出现则按普通棋子登记（绿色实心点，收取或连续 40 秒未观测即从图上隐藏），不强制下一趟回收。仅当观测与本趟已记账的棋子近期轨迹唯一匹配、并明显位于线外时才冲回原区一枚。模糊关联只更新地图，同次观测一棋一轨。正常后撤多留 20 cm 视距。目标分区四角都在画面内时，对区内检测框逐帧去重，仅用连续三帧共同支持的最大可见数更新分区估计；遮挡仍可能导致少计。区内不建立棋子轨迹，靠线处是否适合普通接近仍由安全条件决定。
5. **裁判。** 棋子中心水平投影在己方矩形内（含边界）立即得分，离开即扣回。目标为每 10 秒净得分。分区占用是策略估计，不是裁判真值。摄像头标定、摩擦与载棋估计仍需实车验证。
