# 自主推棋仿真：方法与进度

**进度快照：2026-11-17（中国标准时间）。** 物理场景和「单路车载 RGB + 理想自车位姿」的推棋闭环已在项目工作区运行，能在部分随机布局得分，但 **32 枚随机棋稳定得分、实车 VIO 和实车自主推棋均未验收**。实验现已暂停。本目录先记录方法和证据；运行程序、模型权重、原始日志、视频和检查点尚未迁入，当前不能仅凭本仓库一键复现。

## 仿真怎么做

- **场景与资产。** 在 3 m × 2 m 场地内模拟 RASPBOT V2 麦轮底盘、前置推板和 32 枚棋子。场地用原喷绘布局，白底、顶部照明；棋子视觉模型与直径 47 mm、高 15 mm 的圆柱碰撞体分开。车体仿真网格为近似、推板碰撞体分为凸块，棋子质量与摩擦未做实车标定。资产入口：[场地及区域配置](../assets/field/field.json)、[车体及碰撞配置](../assets/robot/simulation.json)、[棋子配置](../assets/chess/chess.json)。场地配置以左下角为原点、X 向右、Y 向上；资产或接口的具体单位以各自文件为准。
- **传感器与真值隔离。** 运行策略只读取前视 RGB、同一时刻的自车位置和航向、仿真时钟及静态配置。自车位姿由模拟器直接提供，用于先验证推棋，不代表已实现视觉惯性定位。俯视画面、棋子真实坐标、接触和计分只供独立裁判、标注及复盘，不给策略使用。早期真值控制探针是独立的物理验证，不算自主推棋成绩。
- **闭环。** 前视 RGB → 单类 YOLO 检出棋子 → 用相机标定和相应时刻的自车位姿把观测映射到场地 → 更新棋子轨迹、观测时效和世界模型 → 选单棋或可一起推的棋组 → 规划绕后、对齐、推送及脱板/退让 → 输出四路整数 PWM → 相机重新采样。失联记为未知，不把漏检当净空，也不把推板运动当棋子已入区。真实车辆预留「相机 + IMU → VIO → 对齐场地坐标」分支；尚未上实车验证，也不将纯 RGB 导航的试验结果混作 VIO。
- **时序基线。** 已归档的分层复核使用物理 240 Hz、控制 10 Hz、新 RGB 5 Hz、PWM 模型队列延迟 25 ms。它们是已有仿真基线，不是实车实测参数，也不表示最新分支已经完成异步控制验收。

## 怎么比较

1. 先用已知短场景分别检查检测、投影、跟踪、接触和恢复，再在固定布局跑整局回归，最后用**独立的新随机布局**做配对。整局一般为 32 枚棋、120 仿真秒；同一对冻结初始布局和其余参数。本轮保持 PWM 档位和运动速度不变，优先比较从决策到有效推送、以及推后恢复的耗时。
2. **只向己方区规划，也只计己方分。** 独立裁判检查棋子完整入区、持续至少 0.5 秒才有效，离区扣回。对方区误推单列，不因车经过对方区域而判我方得分，也不把该区域当禁行区。回放采样中未见碰边，不等于证明全过程都没碰过。
3. 主报终局净留区枚数、同批平均净枚数 ÷ 32（完成度）、零分局和首分时间；同分时可比较全程平均净在区枚数。另看首组脱板后是否保分、是否能独立完成第二组。场地图上的印刷区域与历史实验评分边界不完全相同，复现时必须冻结实际裁判配置，不得用喷绘框替代或把它当正式比赛规则。

## 已验证到哪里

| 项目 | 已核对的结果 | 结论 |
| --- | --- | --- |
| 早期物理场景 | 真值控制下单棋 15/15；32 棋场景运行 60 仿真秒，无数值发散，最大接触穿透约 0.41 mm。 | 验证了接触与数值稳定性，不代表棋子视觉识别或自主策略通过。 |
| 多组推送开发例 | 一个已见近棋布局从发车点完整运行 120 秒，连续处理两组，终局净 4 枚；首组三枚留区，第二组新得分棋在终局前已脱板。 | 仅开发例；末端视觉仍不足以确认完整入区，策略没有读取裁判确认，不能外推到随机场。 |
| 坐标映射 | 固定 YOLO 框对照，理想像素平均误差 7.30 → 3.85 mm，真实框近距候选总体均值 16.91 → 16.78 mm，但推棋视角 P95 由 13.54 → 15.48 mm。 | 保留原棋顶面投影和标定，不将几何对照当成真实检测输入的增益。 |
| 只送己方区（037 / 026A） | 相同速度的开发回归中，代表局己方净数 3 → 6；10 Hz 回放里触及对方区边缘的棋由 5 枚变为 0 枚。另两套固定布局己方净数为 4 → 5、6 → 6。 | 落实己方目标及计分修正；这是小样本回归，不保证任意布局。 |
| 换手策略（037 / 027） | 四局新布局配对，两版均只送己方区：普通局 2 → 4，近棋局 4 → 0；四局均无对方有效入区。 | 收益不稳定，不切换默认策略。 |
| 近场恢复诊断（037 / 029） | 零分复现局于 113.1 s 退开时，裁判回查棋距完整入区约 27 mm，且策略已约 8 s 未得到该棋有效定位。调整仿真相机观测后 114.4 s 重获两个框，114.8 s 形成新轨迹；逐框核对为原来的同两枚棋，但旧任务没有接回新轨迹，两段尾程 PWM 未发生变化。正常脱板对照片段未触发调整。 | 证实「能找回棋」，未证实「能恢复推送或得分」。保留 115.4 s 检查点；独立新布局未运行，未提升为默认。 |

历史分层实验可对照 [阶段进度](https://github.com/Jyikove/mydot/blob/main/status.md) 和 [六层架构设计](https://github.com/Jyikove/mydot/blob/main/tasks/036-autonomous-collection-architecture.md)；设计稿里的建议参数不等于实测配置。最新实测回放及检查点保留在项目工作区，不随本文档上传。

## 恢复后的优先验证（未开始）

先从 115.4 s 检查点隔离验证「新轨迹接回原任务」：对照正常脱板和容易误关联的相邻棋，确认只有在停车后得到新鲜观测、位置和方向匹配时才允许重接，不盲推。若短测通过，再以不变的车速和评分配置跑固定回归与新随机整局；同时记录是否真的恢复了推送、是否离区扣回，以及是否误推对方区。最后另行验证 VIO 和真实接触参数，不用仿真成绩替代实车验证。
