# 双车对抗仿真

两个策略进程共享一个 MuJoCo 场景。两车在同一个仿真时刻收到各自观测，两条指令共同作用于接下来的 24 个物理步。物理频率 240 Hz，控制频率 10 Hz，车载相机 5 Hz。场地、推板、棋子和麦轮驱动力沿用仓库资产。

## 运行一场对照

在平台 worktree 根目录，使用已装好 `sim/requirements.txt` 的 Python。录像需要 ffmpeg。

```sh
python sim/duel.py --seed 77 --swap --video
python sim/duel.py --a /path/to/chess-a/sim/policies/near_side.py \
  --b /path/to/chess-b/sim/policies/behind_pile.py --seed 77 --swap --video
python -m unittest discover -s sim/tests
```

`--swap` 用同一盘棋再跑一场，交换两个策略的阵营、发车位和球门。每场净比赛时间 120 秒，报告汇总每个策略换边后的总分。日志包含策略文件哈希、所属 Git 提交、工作区脏状态、双方逐步 PWM、最终有效棋子、接触事件及复位。结果自动写入仓库同级的 `三维仿真/报告`，录像写入 `三维仿真/视频`。可用 `SIM_ARTIFACTS_ROOT` 指定仓库外的其他目录。

两边对话在各自 worktree 提交策略。评价固定版本时使用干净的 worktree 或从指定提交建立的独立检出，同时固定策略引用的模型文件。默认对手是两条用编码器和航向执行的开局基线，便于验证双车平台与接触行为。策略可以自行加载 YOLO、分值 CNN 或其他本地模型。

## 策略接口

策略入口为 Python 文件，导出 `Policy` 类。构造函数收 `setup`，包含阵营、发车中心和航向、球门边界、场地尺寸、相机标定和电机顺序。

`act(obs)` 每 0.1 秒调用一次，返回 `{"motor_pwm": [FL, FR, RL, RR]}`，PWM 为 −255 至 255 的整数。车体系 X 前、Y 左，偏航逆时针为正。场地原点为甲队发车侧左下内角，位置用米、角度用弧度、时钟用秒。观测字段如下。

- `rgb` 为只读的 640×480 RGB，相机时间戳见 `image_time_s`，两次控制可能引用同一帧。
- `yaw_from_start_rad` 为相对本队发车航向的理想模拟 IMU 航向，`gyro_z_rad_s` 为模拟陀螺仪 Z 轴角速度。
- `encoder_m` 为四轮模型的累计轮行程，含滑移影响带来的里程误差。起点由公开发车位置确定。
- `time_s` 是比赛仿真时钟，`dt_s` 为控制周期。裁判复位后 `reset_id` 递增，两车轮行程归零。
- 两方各自的策略进程只收到上述传感器输入。场景实例、棋子和对手位姿、比赛比分均留在仿真裁判进程。进程隔离用于接口隔离，双方应运行可信的本地策略代码。

## 裁判口径

依据区赛参考细则第 4–7 节，双方可推动任一颜色棋子。终场按本方球门内的本方棋子分值计分。以接触地面的 MuJoCo 记录和圆柱完整水平投影判定，投影必须严格在印刷线内侧。上层棋、压线棋和对方棋不计分。终场车轮指令归零，场景静止后核分，超过 5 秒仍未静止的结果标记为待复核。

记录偶发接触，不自动扣分。持续相互接触、双方持续尝试运动且都低速三秒，仿真裁判暂停并尝试将两辆车放回本方发车区，棋子位置保留。发车位置被棋子占据时记录待复核。单方策略超时、异常退出或返回无效指令时，该车的 PWM 归零，比赛继续。恶意碰撞、扣分等由人工复核。对练的终场同分按平局记录，金球加赛和实测车辆质量裁决由正式赛制另行处理。
